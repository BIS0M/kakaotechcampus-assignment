## AI 활용 내역
AI를 활용해 구현하거나 수정한 내용을 기록해요.
단순히 어떤 프롬프트를 썼는지보다, 어떤 결과를 받았고 어떻게 수정했는지를 중심으로 작성해요.

### Todo CRUD 구현하기
- AI 활용 내용 :
다음 프롬프트를 사용하여 기본 기능을 개발했어요. 입력창, 추가 버튼, 투두 목록이 포함된 HTML 레이아웃과 수정 / 완료 / 삭제 버튼이 각 항목에 달린 기본 CRUD 코드를 받았어요.
```
Todo 앱의 HTML 레이아웃과 기본 CRUD 기능을 만들어줘.
- 텍스트 입력창과 추가 버튼으로 Todo를 생성할 수 있어야 해
- 생성된 Todo는 목록으로 표시되고, 각 항목마다 수정 / 완료 / 삭제 버튼이 있어야 해
- 입력값이 비어있으면 Todo가 생성되지 않고 안내 메시지를 표시해줘
- 완료된 Todo는 텍스트에 취소선이 표시되어야 해
```
- 직접 수정한 부분 : 수정 기능을 `prompt()` 팝업이 아니라 항목 안에서 바로 입력하는 인라인 입력창 방식으로 바꿨어요. 수정 버튼을 누르면 해당 항목이 입력창으로 바뀌고, Enter 키나 '저장' 버튼으로 값을 반영하도록 `createEditInput` / `saveEditing` 함수를 작성했어요.
- 수정 이유 : `prompt()`는 화면 흐름이 끊기고 모바일 환경에서 불편하다고 느꼈고, 항목 안에서 바로 고치는 편이 실제 사용 경험에 더 가깝다고 생각했어요.

### 상태별 필터링 + 날짜별 관리
- AI 활용 내용 : 전체 / 진행 중 / 완료 탭으로 목록을 거르는 로직과, 각 Todo에 날짜 키(`date`)를 부여해 선택한 날짜의 Todo만 보여주는 구조를 AI와 함께 설계했어요.
- 직접 수정한 부분 : 필터(상태)와 날짜 조건을 한 번에 적용하도록 `getFilteredTodos`를 "① 선택 날짜로 먼저 추리고 → ② 상태 필터 적용" 두 단계로 직접 정리했어요.
- 수정 이유 : 필터와 날짜 조건이 섞여 있으면 동작을 예측하기 어려워서, 조건을 단계별로 분리해 읽기 쉽게 만들고 싶었어요.

### 주간 뷰 (도전)
- AI 활용 내용 : 선택한 날짜가 속한 주의 월~일 7칸을 그리고, 각 칸에 그 날짜의 Todo 개수를 배지로 표시하는 코드를 받았어요.
- 직접 수정한 부분 : 오늘 날짜 강조(`is-today`)와 선택 날짜 강조(`is-selected`)를 분리하고, 개수가 0인 배지는 투명 처리해 레이아웃이 흔들리지 않도록 CSS를 조정했어요.
- 수정 이유 : '오늘'과 '내가 선택한 날짜'는 다른 의미인데 같은 스타일이면 헷갈려서, 시각적으로 구분되도록 만들고 싶었어요.

> ※ 위 AI 활용 내역은 실제로 사용한 프롬프트와 수정 과정에 맞게 자유롭게 고쳐 주세요.

## 구현하면서 고민한 점
구현 과정에서 막혔던 부분이나 고민했던 내용, 해결 방법을 자유롭게 작성해요.
- 고민한 점 : 추가 / 수정 / 완료 / 삭제마다 화면을 어떻게 갱신할지 고민했어요. 매번 DOM을 부분적으로 고치다 보니 상태와 화면이 어긋나는 경우가 생겼어요.
- 해결 방법 : `todos` 배열을 단일 상태로 두고, 변경이 일어나면 `render()`로 목록을 통째로 다시 그리는 방식으로 통일했어요. 또 변경 함수마다 `saveTodos()`를 호출해 상태와 localStorage를 항상 같이 맞췄어요.
